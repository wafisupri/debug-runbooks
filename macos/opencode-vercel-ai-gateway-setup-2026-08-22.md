# OpenCode + Vercel AI Gateway Setup (Free-Tier Model Labeling)

**Date:** 2026-08-22  
**Status:** Fixed  
**Platform:** macOS  

---

## 1. Summary

Connected **OpenCode CLI** to the **Vercel AI Gateway** (`ai-gateway.vercel.sh`) so the 235 gateway language models appear in the OpenCode `/model` picker. The API key is generated by the Vercel CLI and stored in the **macOS Keychain** (not in a plaintext file), exported into the shell via `~/.zshrc`.

The main deliverable beyond the basic connection was a **verified (Free)/(Paid) label for every language model**, so the `/model` filter (`free`) shows only models usable on the $5/month free tier without a credit card. This required **live API testing**, because the Vercel free-tier page, pricing, and model metadata (`tags`, `pricing`) do **not** reliably predict free-tier access.

Final result: **139 language models labeled (Free)**, **96 labeled (Paid)** out of 235. All existing OpenCode providers (TokenRouter, OmniRoute, 9Router, Ollama) were preserved.

## 3. Symptoms

1. **Empty Vercel provider after `vercel ai-gateway coding-agents setup`**:
   The setup command wrote `"vercel": {}` (no `models` list) into `opencode.json`, so all 235 models were invisible in `/model` until explicit `models` entries were added.
2. **Naive parallel free-tier probing returned the wrong verdict**:
   A concurrent 8-worker probe of all 235 models produced **232 × HTTP 429** with the message `Free tier requests on this model are rate-limited` and only **3 × 200**. This looked like "almost everything is blocked," but it was actually the **global free-tier rate limiter** tripping before the per-model access check ran.
3. **Manual single requests behaved differently**:
   - A known-cheap model (`openai/gpt-oss-20b`) → `200 OK`.
   - A blocked model (`deepseek/deepseek-v3.2` at the time) → `{"error":{"message":"Free tier users do not have access to this model...","type":"no_providers_available"}}`.
   The distinction between the two error classes was critical (see Root Cause).

---

## 4. Root Cause

1. **OpenCode already knows the `vercel` provider natively** (`models.dev` defines it as `Vercel AI Gateway`, npm `@ai-sdk/gateway`, env `AI_GATEWAY_API_KEY`, 350 models). The setup command therefore only needs an empty `"vercel": {}` block plus the API key — but models only show in the picker if a `models` map is present in `opencode.json`.
2. **Two different "not allowed" responses exist on the free tier**:
   - **Hard block** (`type: no_providers_available`, message contains `Free tier users do not have access to this model`) → model requires paid credits → **(Paid)**.
   - **Rate limit** (`HTTP 429`, message `Free tier requests on this model are rate-limited`) → model *is* free-tier accessible, the request just exceeded the strict **global per-key rate limit** → **(Free)** but throttle-prone.
   When hammering many models in parallel, the global limiter fires **before** the access check, so every model returns the 429 rate-limit shape and the true Paid/Free split is hidden.
3. **A `400 max_output_tokens` / `max_tokens must be at least 16` is NOT a block.** The request reached the provider, which rejected the tiny param — proving the model is reachable on the free tier. These must be treated as **(Free)**, not errors.

---

## 5. What Did Not Work

- **Parallel probing (8 workers)** of all 235 models: tripped the global rate limit, producing 232 false "rate-limited" results and no usable labels.
- **Assuming the Vercel free-tier web page encodes eligibility**: visiting `https://vercel.com/ai-gateway/models?freeTier=true` returns all 330 models (the filter is client-side JS and is ignored by the `/v1/models` API). Only **1** language model carries a `free` tag in metadata — so tags are useless for this.
- **Looking for a free-tier flag in the API model objects** (`pricing`, `tags`, `zdr`, etc.): none reliably indicates free-tier access. Pricing is misleading — cheap models (e.g. DeepSeek) can still be hard-blocked.
- **Trying to classify by provider/price heuristics**: DeepSeek is cheap but was hard-blocked during the run, so inference by price is unsafe.

## 6. Final Fix

### 1. Connect the gateway (creates Keychain key + provider block + shell export)
```bash
vercel login                      # already logged in as wfspr
vercel ai-gateway coding-agents setup --agent opencode
```
This:
- Creates an API key stored in **macOS Keychain** under service `Vercel AI Gateway` / account `vercel-ai-gateway`.
- Adds `"vercel": {}` to `~/.config/opencode/opencode.json` (OpenCode's native provider registry fills in npm `@ai-sdk/gateway` and the `AI_GATEWAY_API_KEY` env).
- Appends to `~/.zshrc`:
  ```sh
  # >>> vercel ai-gateway >>>
  export AI_GATEWAY_API_KEY="$(/usr/bin/security find-generic-password -s 'Vercel AI Gateway' -a 'vercel-ai-gateway' -w 2>/dev/null)"
  # <<< vercel ai-gateway <<<
  ```

### 2. Label models by live sequential testing
Live-test each language model one at a time with a tiny completion (`max_tokens=16` to avoid the `max_output_tokens` 400), with **adaptive backoff** so the global rate limiter is never saturated:
- Start ~30s between requests; if a `429` appears, back off 150s and increase spacing (cap ~90s); after a streak of successes, ease spacing back down.
- Each non-429 response is definitive:
  - `200 OK` → **(Free)**
  - `no_providers_available` / `Free tier users do not have access` → **(Paid)**
  - `400 max_output_tokens` / `max_tokens must be at least 16` → **(Free)** (reached provider)
  - `404` / `deprecated` / `not accessible with the current access profile` → **(Paid)** (unavailable to free account)
- Transient `URLError`/DNS blips and leftover `429`s: re-test once steady; if still unresolvable, infer from the model family (e.g. an `opus-5-*` line that keeps rate-limiting is Paid).

### 3. Merge labels into OpenCode config (overwrite `"vercel": {}` with a `models` map)
```jsonc
"vercel": {
  "models": {
    "openai/gpt-oss-20b": { "name": "GPT-OSS 20B (Free)" },
    "anthropic/claude-opus-5": { "name": "Claude Opus 5 (Paid)" }
    /* ... all 235 language models ... */
  }
}
```
The display `name` carries the `(Free)` / `(Paid)` suffix so `/model` filtering on `free` shows only the 139 usable models.

```bash

```

### Single live access probe (the definitive test)
```bash
curl -s https://ai-gateway.vercel.sh/v1/chat/completions \
  -H "Authorization: Bearer $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-oss-20b","messages":[{"role":"user","content":"hi"}],"max_tokens":16}'
# 200  -> Free-tier accessible
# {"error":... "Free tier users do not have access to this model" ...} -> Paid
```

### OpenCode
```bash
opencode            # then /model, type "free" to filter the 139 (Free) models
```

## 11. If This Happens Again

1. **`/model` shows no Vercel models**: confirm `provider.vercel.models` map exists in `opencode.json` (setup only writes `"vercel": {}`). Re-run the merge step with the latest `/v1/models` dump.
2. **All probes return `429 rate-limited`**: stop hammering. The global free-tier limiter is tripped — wait ~4 minutes of silence, then probe **sequentially** with ≥20s spacing. A 429 during testing means the model is Free, not blocked.
3. **A model returns `no_providers_available` / "do not have access"**: that model is Paid — label it `(Paid)`.
4. **Re-label after a Vercel catalog change**: re-fetch `/v1/models`, re-run the sequential tester, re-merge. Expect the DeepSeek/OpenAI-gpt-3.5-turbo edge cases (400 max_tokens) to need the `max_tokens>=16` adjustment.
